# 4モニター・共有起動

`GameRoom.prefab` をワールドに配置すると、中央を囲む4枚の16:9モニターを使えます。既存の1枚を現在のシーンで拡張する場合は **Game Select > Create Four Monitor Room**。モニターは中心から4m、表示中心の高さ2.1mです。各モニターのTransformで位置や向きを調整できます。

## 共通操作

- どのモニターからでもゲームを選択してPLAYできます。
- 1枚で開くと、そのインスタンス内の全プレイヤーの4枚すべてに同じゲームが開きます。
- どのゲーム画面から戻っても、全モニターが選択画面へ戻ります。
- 大富豪は本体未実装なので、共通の準備中画面が開きます。
- 起動中は別ゲームへの開始要求を受け付けません。戻ってから別ゲームを選択します。
- カーソル・選択途中のカルーセルは各モニター／各プレイヤーのローカル操作です。

## 同期範囲

GameRoomSessionの所有者だけが `activeGameId` を更新し、Manual同期します。モニターからの開始・終了要求は所有者へのNetworkCallableイベントです。開始通知だけでなく現在のIDを同期変数に保存するため、途中参加者にもOnDeserializationで現在のゲームを表示できます。所有者交代時は保存済み状態を再適用します。

**この版はモニターと起動・終了同期までです。** 得点・手札・配札・ターン・勝敗の同期や大富豪本体は含みません。おやつ工房の所持数・設備はモニターごとのローカル状態です。

## ゲームパッケージとの接続

ゲーム側が `public UdonBehaviour sessionController;` を持つ場合、部屋の生成・カタログ更新時に自動で設定します。戻るボタンでは次を呼びます。

```csharp
sessionController.SendCustomNetworkEvent(NetworkEventTarget.Owner, "RequestClose");
```

単体パネルではsessionControllerはnullです。その場合のローカル終了動作もゲーム側に用意してください。ゲーム固有型を共通側から参照しないため、フォルダー単位の追加・削除を維持しています。

## 検証

ClientSimで東側から全4枚の起動、西側から全4枚の終了、大富豪の準備中表示、無効なIDの拒否、受信状態の再適用、重複受信時に進行をリセットしないことを確認しました。コンソールエラーは0件。4画面の描画も確認しています。

OnDeserializationの復元経路はローカルで検証済みですが、異なるPC・VRChat実クライアント間のネットワーク試験は未実施です。公開ワールドで使う前に複数クライアントと途中参加で確認してください。

選択画面左下の時計は端末のローカル時刻（HH:mm）を1秒ごとに更新します。時刻はネットワーク同期しません。
